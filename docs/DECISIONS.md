# Decisions

Short records of architectural choices: what we chose and why.

| #   | Decision                                                                                                                                                                                                                                                          | Why                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | A pnpm monorepo with `apps/web`, `apps/api`, `packages/db` and `packages/domain`.                                                                                                                                                                                 | The contact window, scoring and validation rules have to be identical on the phone and on the server. A shared package keeps one copy.                                                                                                                                                                                                                                                                                           |
| D2  | One Next.js App Router PWA serves both the officer UI (phone) and the manager UI (desktop).                                                                                                                                                                       | There's one codebase and one deployment. A PWA installs from a link, with no app-store step.                                                                                                                                                                                                                                                                                                                                     |
| D3  | Next.js rewrites `/api/*` to the Fastify API, so the browser only ever talks to the web origin.                                                                                                                                                                   | Auth cookies stay first-party, the API needs no CORS, and in production the API URL is an environment variable.                                                                                                                                                                                                                                                                                                                  |
| D4  | The API is a separate Fastify app with a `buildApp()` factory.                                                                                                                                                                                                    | It keeps a clean boundary for sync and import endpoints. Tests call `app.inject()` without opening a port, and the API can scale or move without touching the web app.                                                                                                                                                                                                                                                           |
| D5  | PostgreSQL 16 with Prisma 7: `prisma.config.ts`, the `prisma-client` generator and `@prisma/adapter-pg`.                                                                                                                                                          | The data is relational (loans, snapshots, assignments) and the schema is typed. Prisma 7 is the current stable major.                                                                                                                                                                                                                                                                                                            |
| D6  | Better Auth with email and password. `User` has `role` (OFFICER, BRANCH_MANAGER or HEAD) and `branchId`. Every data query goes through one scope helper.                                                                                                          | Access control sits in one place that can be tested: officers see only their assigned loans, and managers see only their own branch. Anything outside that scope returns 404, not 403.                                                                                                                                                                                                                                           |
| D7  | The offline outbox (Dexie) holds append-only events: contact attempts and outcomes. Each event carries a client-generated UUID, which the server upserts on.                                                                                                      | Retries are safe, and events never need merging because nothing is edited in place. Derived state, such as the latest promise, is computed on the server.                                                                                                                                                                                                                                                                        |
| D8  | The priority score comes from a logistic regression, trained offline, stored as versioned JSON coefficients and evaluated in TypeScript. Its reasons are the three largest feature contributions. No LLM is used in scoring.                                      | It is deterministic and auditable, and the reasons are true by construction. A lender has to be able to explain why one borrower was chased before another.                                                                                                                                                                                                                                                                      |
| D9  | The contact window `[08:00, 19:00)` IST is a pure function in `@kisht/domain`. The client uses it to grey out buttons, and the server has the final say. Events are judged by when they happened (device time corrected for clock skew), not by when they synced. | An outcome logged offline at 18:50 and synced at 21:00 is legitimate. A tampered device clock is not.                                                                                                                                                                                                                                                                                                                            |
| D10 | Roll rates are computed from a daily `LoanSnapshot` row per loan, written by each import.                                                                                                                                                                         | Cohort roll rates need daily DPD history. The import is the source of truth.                                                                                                                                                                                                                                                                                                                                                     |
| D11 | SMS and WhatsApp are mocked: "sent" messages are written to a `MessageLog` table. Call buttons open `tel:` links, and map buttons open a Google Maps URL.                                                                                                         | Outside systems are out of scope. A map SDK would be too heavy for 2–3 GB phones.                                                                                                                                                                                                                                                                                                                                                |
| D12 | Pinned versions: Prisma 7.10.1 (npm `latest` is an 8.0 release candidate), Better Auth 1.7.15 with its `auth` CLI (`@better-auth/cli` is stale), and TypeScript 6.0.3 (TS 7's native compiler isn't yet supported by all of our tooling).                         | We need stable, supported versions for a one-week build.                                                                                                                                                                                                                                                                                                                                                                         |
| D13 | Demo clock: in demo mode only, anyone signed in can move the server's clock. The route doesn't exist otherwise, a banner shows while it's active, and the server's rules move with it.                                                                            | Without it, a reviewer opening the app at night (IST) would find every contact blocked, as the rules require. It also lets browser tests pass at any hour.                                                                                                                                                                                                                                                                       |
| D14 | App pages are client components over a prerendered static shell; data comes from `/api` through TanStack Query.                                                                                                                                                   | The officer screens must open with no network (service worker plus a local cache, day 4). Server-rendered pages would need the server for every navigation. The API enforces all access; the client guard only routes people.                                                                                                                                                                                                    |
| D15 | A small typed dictionary for Hindi and English instead of an i18n library.                                                                                                                                                                                        | Two languages and a few hundred strings. TypeScript checks every key exists in both, and it adds nothing to the bundle on low-end phones.                                                                                                                                                                                                                                                                                        |
| D16 | A `contracts` package of zod schemas for every API request and response, used by Fastify (through `fastify-type-provider-zod`) and by the web client.                                                                                                             | One wire format instead of hand-copied types on each side. Responses are serialised through their schema, so unlisted fields can't leak, and the same schemas generate the OpenAPI docs.                                                                                                                                                                                                                                         |
| D17 | The API is split into feature modules (`routes.ts` for HTTP, `service.ts` for logic), each registered with one explicit `AppContext`. All access filters come from `modules/auth/scope.ts`.                                                                       | Every feature has the same shape, nothing depends on globals, and the access rules can't drift between features.                                                                                                                                                                                                                                                                                                                 |
| D18 | Package boundaries are enforced by lint (Biome `noRestrictedImports`), and the domain package carries a coverage threshold.                                                                                                                                       | Architecture that is only a convention erodes. CI makes the dependency rule and the bar for business-rule tests impossible to skip.                                                                                                                                                                                                                                                                                              |
| D19 | Today's list and the loan screen send the full phone number to the officer holding that loan, and to nobody else. It stays masked on screen, and every Call tap is recorded.                                                                                      | Calls often work when data doesn't, so an officer must be able to dial with no signal (day 4). Scope limits it to their own short list, and managers still get masked numbers with an audited reveal.                                                                                                                                                                                                                            |
| D20 | Every sync batch states what the phone's clock read when it was sent. The server corrects each event by the gap to its own clock.                                                                                                                                 | Setting a phone back to look inside the 8 am–7 pm window changes nothing, because both readings shift together.                                                                                                                                                                                                                                                                                                                  |
| D21 | Ranking puts 1–30 loans first, then rupees at stake.                                                                                                                                                                                                              | The back-test showed a model mixing all stages lost to a one-line rule. See [MODEL.md](MODEL.md).                                                                                                                                                                                                                                                                                                                                |
| D22 | The Today payload holds the officer's whole day, including each loan's recent history. The loan screen reads from it, on one static page addressed by query string.                                                                                               | The loan screen needs no network and no extra requests on weak signal, and one cached page serves every loan offline.                                                                                                                                                                                                                                                                                                            |
| D23 | System fonts instead of web fonts.                                                                                                                                                                                                                                | Measured: web fonts cost 415 KB, more than all our code, on the patchy connections the brief describes. Android, Windows and Mac all ship good Latin and Devanagari faces. The cost is small differences between platforms.                                                                                                                                                                                                      |
| D24 | Reminders run on a timer inside the API process, claim each row before sending, and write to `MessageLog` instead of a gateway.                                                                                                                                   | One dispatcher is enough at this scale, and claiming makes a double run harmless. Moving to a real SMS gateway changes one function.                                                                                                                                                                                                                                                                                             |
| D25 | Charts are small hand-written SVG components, each with a table view. Series colours were run through a colour-blindness validator on both themes.                                                                                                                | The dashboard needs two chart forms. A chart library would outweigh all of our own code.                                                                                                                                                                                                                                                                                                                                         |
| D26 | The weekly back-test runs on first request after a week's results are in, and each finished week is stored.                                                                                                                                                       | No scheduler to operate at this scale, and a finished week's result never changes afterwards.                                                                                                                                                                                                                                                                                                                                    |
| D27 | The Today list shows the phone's copy at once and refreshes behind it, and every field request has a timeout.                                                                                                                                                     | Weak signal hangs rather than fails. An officer standing in a shop shouldn't watch a spinner for a list they already have.                                                                                                                                                                                                                                                                                                       |
| D28 | Sheets are native `<dialog>` elements, with a strict Content-Security-Policy and security headers on every page.                                                                                                                                                  | The browser provides the focus trap and Esc correctly, for less code. Nothing loads from any other origin, so injected content has nowhere to send data.                                                                                                                                                                                                                                                                         |
| D29 | The sign-in rate limit is stored in Postgres, with counts over a day old purged.                                                                                                                                                                                  | Held in memory, a restart reset it and each extra API instance counted separately. The keys contain IP addresses, so they aren't kept. Each sign-in costs a couple of small queries, which is nothing at this volume.                                                                                                                                                                                                            |
| D30 | The Content-Security-Policy keeps `'unsafe-inline'` for scripts instead of using nonces.                                                                                                                                                                          | A nonce must be generated per response, so every page would have to be rendered on the server per request, giving up the prerendered shell (D14) that makes weak-signal and offline opening fast. Inline scripts are limited to Next's bootstrap and our theme script, no user content is rendered as HTML, and `connect-src 'self'` leaves injected code nowhere to send data. Revisit if the app ever renders outside content. |
